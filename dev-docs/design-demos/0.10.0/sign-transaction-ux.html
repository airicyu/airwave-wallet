簽署交易 popout

非正式契約。殼層對齊簽署訊息。主舞台是模擬結果：簽署帳戶預期的 SOL／代幣變動。 指令與 program 名稱放在預設收合的「交易明細」。示範 https://swap.example.test、4aF1…pda4。批准＝簽名，不代廣播。

Popout 384×600

畫面意圖

非正式帳戶與站點不要做成輸入列。與簽署訊息同一套審批殼。

  • 頂欄左：Home 同款 widget（名稱／前 4…後 4）＋複製。不是切換器。
  • 主區最上中央「簽署交易」，再來站點 chip。
  • 其下主舞台：模擬得到的 SOL／代幣預期變動。成功不另標「會成功」。
  • 預計會失敗：預期變動上方一張 notice（一句原因；「失敗詳情」收合在同一張卡片內）。
  • 再下：「交易明細」可展開卡片，預設收合。內含指令列（program 名）、費用、原始交易。
  • 鎖定：與簽署訊息同一套整頁解鎖（Airwave、錢包已鎖定、密碼欄、內容區「解鎖」）。無帳戶頂欄、無殼底。解鎖後約 0.7 秒批准 disabled。
  • 載入失敗：標題可留；主體「請求已不在」；兩鈕 disabled。

主舞台：模擬

成功只秀變動。失敗才出 notice，不把錯誤塞進預期變動標題。RPC 做不到用「無法模擬」notice，沒有 program logs 就不畫失敗詳情。不自動拒絕。

交易明細（輔助）

單位仍是 compiled instruction 陣列，不是「主程式」。每列：序號、該列 programId（熟名或縮寫）。對不出 data 不猜。同一 program 兩次就兩列。不依 program 分組。CPI 不在已簽訊息裡，明細也不畫 inner ix。
