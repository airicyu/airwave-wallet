# 0.28.0 — 為何這樣載入更舊 Activity

## 問題

0.18.0 刻意只抓 20 筆、不翻頁，避免一次打爆 RPC／Helius。帳戶歷史超過 20 筆時，使用者無法在錢包裡看到更舊的列。

## 否決

| 方案 | 為何否 |
|------|--------|
| 把 `limit` 調到 100／1000 | 第一屏變慢，仍有上限，不是「還有就再載」 |
| 「載入更多」按鈕 | 與「捲到底繼續看時間序」重複；本版觸發是捲動 |
| 下一頁失敗用整頁 `error.activityLoad` | 使用者已看到前面的列，整頁錯誤像資料沒了 |
| 下一頁失敗用限流 toast | toast 約 4 秒消失，錯誤與「列表尾端還有更舊的」脫鉤 |
| 停在底部自動重試 | 失敗會連打 RPC／Helius |
| 可見「正在載入下一頁」 | 第一頁已有安靜載入中；底欄用 widget 即可 |
| 活動進 `chrome.storage` | 0.18.0 已否；歷史會過期、還有隱私面 |
| 相對時間或 `M/D` | 過幾週變成 `6/1`，缺少年份與時刻，翻舊頁時對不上 |

## 選定

- 每頁仍 20；游標＝畫面上最舊 signature 當 `before`。
- 滿頁才允許再載；短頁當結尾。
- 失敗留列、底欄短句、離開底部再捲才重試。
- 捲動根是 `.screen-body`，符合 design-principles，避免頂欄被整頁捲走。
- 時間用本地 `YYYY-MM-DD HH:MM:SS`，與語言 catalog 無關。
- Icon 用 Enhanced 已有的 mint + 既有 Jupiter／持倉快取，不換 Parsed Events。
