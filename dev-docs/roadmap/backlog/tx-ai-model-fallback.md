# 交易 AI 分析模型備援 — backlog

構想尚未排進某版 INDEX，**不是契約**。排程後以該版 INDEX 為準。

對象是簽署交易的 AI 分析：使用者在 Settings 選的報告模型（OpenRouter）。定級模型若仍分開呼叫，同一套可用性規則是否套用，排進 INDEX 時再定。

## 現況

分析固定打使用者選的那一個模型。該模型下架、地區不可用、或這次請求被拒時，這輪分析失敗。沒有先確認能不能用，也不會改打另一個模型。

## 產品意向

開始分析前先確認所選模型目前可用。不可用就依備援名單改打下一個，直到有一個能承接這輪，或名單用盡。

- 可用性是這次能不能對該模型發出分析，包含下架、地區限制、供應端拒絕。不是餘額或金鑰是否存在；金鑰缺失仍是設定問題，不靠換模型解決。
- 備援順序固定、寫在產品裡。使用者選的模型永遠排第一；它可用就不換。
- 實際承接的模型要讓使用者看得到（分析進行中或結果上的短標）。不要靜默換成另一個模型還顯示原本的名稱。
- 名單全部不可用時，這輪分析失敗，短句說明。不擋模擬與批准。
- 備援只換模型。同一份快照、同一套工具與定級規則。數字與鏈上事實仍由程式產出。

## 開工前仍須拍板（排進 INDEX 時）

- 「可用」是開打前查目錄／供應狀態，還是第一次請求失敗再換。
- 備援名單有哪些模型 id，以及要不要讓使用者改順序。
- 定級模型是否共用這份名單。

## 非目標（構想層）

- 依題目難度自動挑更強的模型
- 同一輪並行打多個模型再投票
- 金鑰、開關、配額用盡時改走別的供應商帳號
