# 0.46.0 — WHY

平時把勾放在眼睛旁邊，看起來像「這一格已經存好」或「必須再按一次才算」，但現碼其實失焦就寫、清空也立刻寫。使用者分不出顯示與提交。

改成鉛筆才進入編輯，確認與捨棄只在編輯出現，是為了讓寫入只發生在明確的確認。捨棄與離開頁面都不寫，避免誤觸輸入框就改掉 gateway 或 API key。

RPC 展開編輯與地址簿改名已經是「先進入才出現勾」。它們沒有這次抱怨的常駐勾，也不在本版範圍；不要順手改成同一套，以免把 URL 清單與名稱列的既有確認方式一起換掉。

概念稿把確認做成綠色、捨棄做成紅色，並在按下時縮小，是為了這兩個新出現的圖示能分開，而且點下去有回饋。不在畫面上加「點鉛筆才編輯」這類句子。
