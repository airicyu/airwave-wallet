# 0.38.0 — 為何未驗證留空、分數只掛已驗證盾

## 問題

Home 名稱後的 Unicode `✓` 與審批列最左盾不一致。0.33.0 兩態都用盾，是為了左欄永遠佔位、防假勾佔第一閱讀位置。空心**灰盾**在使用上仍被讀成「受保護」。分數若出現在未驗證列，會讓該 mint 看起來像被評過、較可信。

## 決策

1. **已驗證才畫盾。** 盾形只表示 Jupiter verified。與 0.33.0 已驗證 SVG 同語意。
2. **未驗證留空、仍佔 26px。** 不畫灰盾、不畫警告三角。三角把「未知」畫成警示，過重。佔位讓圓圖對齊；第一欄仍是錢包 DOM，攻擊方不能把假勾塞進這一格（只能偽造右側 icon／文字，0.33.0 未驗證主標規則仍在）。
3. **分數只掛已驗證盾右下。** 不進代幣圖、不進未驗證格。同一支 Tokens v2，不另打 API。
4. **aria 不含分數。** 列上不加旁白；既有 `token.verified`／`token.notVerified` 足夠。
5. **原生 SOL 兩屏都不畫分。** Home 可能從 wrapped mint 抄到 `organicScore`；審批 native 不查 Jupiter。畫分會兩屏不一致，故一律不掛。

## 否決

| 方案 | 原因 |
|------|------|
| 未驗證空心灰盾 | 盾＝防護 |
| 未驗證警告三角 | 未知≠已判定有害；使用者已否決後改留空 |
| 未驗證仍畫 organic score | 分數像背書 |
| 分數疊在代幣圓上 | 與假 icon 像素不可分 |
| 名稱後 `✓` | 與審批不同序；分數無處掛 |
| 取消最左格、未驗證圓圖左移 | 已驗證／未驗證圓圖不對齊 |
