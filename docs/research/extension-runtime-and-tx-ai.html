Chrome Extension runtime 與交易 AI 隔離

Airwave 是 Manifest V3 的 Solana 錢包。各畫面不是同一個 JS 記憶體，而是各自獨立的 Chrome context。 簽署分析跑在 manifest.sandbox；模型、RPC、金鑰與定級只活在 service worker。

1. 八個獨立 runtime

2. 誰能跟誰說話

真正只有三道通道：頁面 ↔ content 用 window.postMessage； 擴充頁／content／offscreen ↔ SW 用 chrome.runtime； offscreen ↔ sandbox 再用一次綁 event.source 的 postMessage。

頁面 postMessage chrome.runtime ↔ SW 擴充頁命令 offscreen ↔ sandbox

3. 誰持有什麼（狀態與 custody）

持久狀態以 chrome.storage 為真相，UI 用 onChanged 與命令讀鏡像。 Pending 與 AI 報告只活在 SW 記憶體，不寫 storage，也不靠「碰運氣 hydrate」。

資料 住哪 誰可碰 誰絕不可碰
password-boxed vault chrome.storage.local · airwave.vault.v1 僅 SW 解密到記憶體 inject／content／sandbox／offscreen／審批頁
解鎖工作金鑰 SW 記憶體 + storage.session（TRUSTED_CONTEXTS） 僅 SW；瀏覽器關掉即清 任何頁面世界、sandbox
settings／帳戶 meta／連線 storage.local SW 讀寫；擴充頁看公開形狀 OpenRouter key 不進 getState
pending 簽署請求 SW Map SW；UI 用 ui.getPending storage hydrate、content、sandbox
TxAiAssessState SW 記憶體，掛在該 requestId SW 寫；審批頁短輪詢讀 不 persist、不跨 pending 復用
assess 交易快照 SW session · 已清簽名槽 host tools 只打這份副本 sandbox 看不到原始待簽 bytes 當可改物件；CU 變更不更新快照
OpenRouter API key settings 秘密欄，僅擴充頁 secrets 命令可讀全文 SW 打 chat／Decisions 時使用 offscreen、sandbox、公開 getState

錢包殼怎麼選批准面

dApp 的 connect／sign：側欄已開 → uiHost: "sidebar"，通知側欄 overlay；否則開 popout。 錢包自己的 walletSend 留在發起的 popup／sidebar，不另開 popout。 關 popout 會結束對應 pending（walletSend／signAndSend 走各自收尾）。

4. 訊息信任根

信任的是 Chrome sender 與 event.source，不是封包裡自報的 from 字串。 結果只回發起的那一條線，不預設全 tab 廣播。

通道 允許什麼 拒絕什麼
inject → content event.source === window 且 origin 相符；command 在 PAGE_COMMANDS 任意 wallet.*／ui.*；外站偽造
content → SW dapp.*、debug.ping；SW 取 tab origin 擴充頁專用命令（isExtensionPage 擋）
popup／sidebar／popout → SW ui.*、wallet.*、shell.* 網頁 sender 冒充擴充頁
offscreen → SW（airwave-tx-ai） sender.id 是自己、無 tab、URL 含 offscreen content／網頁／假 offscreen
SW → offscreen 無 tab，URL 空或含 service-worker／background 其他擴充頁亂發 assess.start
sandbox ↔ offscreen 只接受自家 iframe／parent 的 event.source 頁面、content、未知 frame

刻意不做的事

不對 inject ↔ extension 每筆結果做 RSA encrypt／decrypt。 不用 chrome.storage 當 event bus。 不把 pending 或 AI 報告寫進 storage 再「重開碰運氣」。

5. 交易 AI 的隔離層

模型只在 sandbox 裡「想下一步叫什麼」；真正出網與碰鏈的動作一律回 SW。 Offscreen 存在的唯一理由：SW 不能直接掛 DOM iframe，所以用它當短命宿主。

service worker 最高特權
  • enqueue 後若開關 on 且 key 非空，自動 assess.start 一次
  • 快照 workingTx ?? 原文並清掉簽名槽
  • 開／關 offscreen；執行 allowlist tools；打 OpenRouter chat
  • 本地算確定性 flags；再打 Decisions；套下限
  • 不把 key／vault／待簽原文交給 sandbox
offscreen 轉發層
  • 建立 sandbox iframe：chrome.runtime.getURL("src/sandbox/index.html")
  • SW 的 assess.start／assess.abort 往下丟
  • sandbox 的 tool／llm.chat／done／fail 往上丟，再把回包 post 回去
  • 不執行 tool、不持 OpenRouter key、不讀 settings 秘密欄、不打 Decisions
sandbox 無網 JS
  • CSP：sandbox allow-scripts; script-src 'self'; object-src 'none'; connect-src 'none'
  • 頁內再加 connect-src 'none'；bundle 是抄入的 agent-harness/loop.ts
  • 最多 12 步：llm.chat → 可選 tool → 產出 reportText
  • 無 chrome.*、無 fetch／XHR／WebSocket、無 vault、無簽名、無 eval 模型字串
審批殼 只消費
  • 條件滿足才掛單列「AI分析」卡（標題下、預期變動上）
  • 短輪詢 ui.getPending 看 txAi；不發明第二條 start
  • refresh／每 3 秒模擬只改預期變動，不重跑 AI
  • 等級再高也不禁用核准；ui.resolvePending 不等 assess

6. 一筆簽署的 AI 流程

只對 signTransaction／signAndSendTransaction／walletSend。 signMessage 不做。同時最多一筆 assess，第二筆排隊；pending 已結束則丟棄。

01
Pending 成功 enqueue

addPending 觸發 hook → maybeStartTxAi。已有 session 則不重入。

SW pending → assess.ts
02
讀 settings，條件不滿足就停

txAiAnalysisEnabled 且 OpenRouter key trim 非空才繼續。否則審批卡也不出現。

03
快照未簽 bytes

複製 workingTx ?? enqueue 原文，簽名槽清成 64 個 0。之後改 CU 不重跑、不改這份副本。

04
確保 offscreen，送 assess.start

payload 含 locale prompt 與 requestId。不含 API key。牆鐘 60s；sandbox 單次 llm.chat／tool 往返 55s。

SW → runtime → offscreen → postMessage → sandbox
05
Sandbox 多輪查詢，回 assess.done

每一步的 chat／tool 都經 offscreen 回到 SW 代打。SW 只承認當前 activeTxAiRequestId。

06
SW 本地 flags → Decisions → 下限 → done

審批頁下一次 ui.getPending 看見等級與報告。點單列卡開 overlay，不重跑。

approval shell ← ui.getPending.txAi ← SW memory
A
sandbox 宣告 ready

offscreen 先把排隊中的 assess.start 沖下去。

B
runSandboxLoop

system + user → callModel。模型若回 tool_calls，逐個 executeTool，結果 clip 到 8000 字再餵回。

C
llm.chat 在 SW

sanitize 訊息（角色、長度、tool_calls 上限）後，用 settings 的報告模型打 /api/v1/chat/completions。

D
tool 在 SW

hostToolVerdict 擋表外名稱；args 字串若提到 sendTransaction 等寫入 RPC 也拒絕。RPC 未就緒則 tool 失敗。

E
結束條件

模型不再叫 tool 且有正文 → assess.done。空回覆會 nudge 一次。12 步用盡取最後一段 assistant 正文。abort／timeout → fail。

G1
確定性 flags 只信 SW

local-flags 對快照算 unknown_program、durable_nonce、authority_change、unlimited_approve、close_account_external、system_assign、owner_mismatch、lookup_account_unchecked。模型或 decode_message 回的 flags 只給模型閱讀，不寫進 TxAiAssessState。

G2
Decisions 只在 SW

POST https://openrouter.ai/api/alpha/decisions，模型用 openRouterDecisionsModel。state 帶報告、SW flags、kind、locale。禁止 secret。

G3
下限只升不降

unlimited_approve／authority_change／close_account_external／system_assign ≥ watch；owner_mismatch ≥ high。鏈讀失敗則不打 Decisions，顯示等級仍可被下限抬起。

X
Pending 結束即丟

takePending／removePending 會 discardTxAi：abort、出隊、關 offscreen（若沒有下一筆）。核准不等待。

Y
失敗仍可簽

timeout、空報告、offscreen 開不起來、Decisions 解析失敗 → error 或 UI「未知」。不擋核准、不擋模擬、不擋改 CU。

Z
兩條模擬互不偷改

審批 ui.simulatePendingTx 用交易自己的 blockhash（0.32）。AI tool simulate 仍 replaceRecentBlockhash: true。共用 RPC helper，旗標由呼叫端傳入。

7. Sandbox 能請求的，只有這些

沒有泛用 rpc(method, params)。名稱含 vault／sign／storage 但不在表內的，一律拒絕。 廣播與改鏈 method 被寫死禁止。

tool.name SW 實際做什麼
decode_message 解碼 assess 快照；回 instructions。其 flags 僅供模型閱讀
get_accounts 唯讀多帳戶（jsonParsed）；可省略 pubkeys，改用上次 decode 記住的鍵
simulate simulateTransaction，replaceRecentBlockhash: true，無 sigVerify
rpc_get_balance getBalance
rpc_get_account_info getAccountInfo（base64 或 jsonParsed）
rpc_get_multiple_accounts getMultipleAccounts，最多 20 個 pubkey
rpc_get_token_accounts_by_owner getTokenAccountsByOwner
rpc_get_signatures_for_address getSignaturesForAddress，limit ≤ 20
rpc_get_transaction getTransaction
rpc_get_latest_blockhash getLatestBlockhash

禁止集合

sendTransaction、sendRawTransaction、requestAirdrop、任意 URL fetch、filesystem、 eval／new Function／動態 import() 未固定 URL、sandbox 直連 OpenRouter。 Host 也不得對模型回傳當碼執行。
