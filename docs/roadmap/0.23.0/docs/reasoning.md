# WHY — 0.23.0

## 為何自製 `t` 而不是 i18next

三種語言、沒有複數／ICU。GUIDELINES 要壓低擴充依賴。typed catalog 在編譯期抓缺譯，套件解決的是我們沒有的問題。語言分支只留在查表與 Settings 寫入。

## 為何預設固定繁體中文

產品至今是繁中。跟瀏覽器走會讓第一次打開變成英文或簡中，設定裡又沒有明顯「被自動選了」。未知碼與缺欄同一條後備，行為可測。

## 為何語言頁用網路那種單選列

design-principles 第 5 節：互斥選擇用列，不用分段 tab 裝「目前是哪一個」。三個語言名（含 English）在 422px 分段裡會擠。和網路同一套，使用者不必學第二種選法。立刻 patch，無整頁 Save。

## 為何摘要用 endonym

介面已是英文時，仍要認得「繁體中文」才能切回去。把摘要譯成 `Traditional Chinese` 反而要對照。

## 為何繁簡同一套中文字體

規劃已選方案 B，且明確不要繁簡分型。正黑／蘋方能畫簡體碼位；筆形偏繁中，換雅黑會讓切語言時版面與字重跟著跳。不打包 webfont，擴充體積與 CSP 都較單純。

## 為何去掉標題 0.02em

那是拉丁字追蹤。漢字會被拉開（「確認中」）。金額等寬字不靠 letter-spacing。

## 為何法律本文本版不譯

篇幅與法務語氣不是 chrome 短句。列名可譯；本文留 `docs/legal` 單一檔，避免未審過的三語法律稿。

## 為何 SW 不譯、只回 code

若 SW 用當下 locale 譯完再寫進持倉 `error` 或模擬 `reason`，切語言時 storage 裡仍是舊譯文，產品句「立刻改文案」會破。錯誤碼穩定、UI 每次 render 再 `t`，與 `chrome.storage.onChanged` 同一條鏡像路徑。SW 也不該依賴 UI catalog。

## 為何產品圖只放三處

圖是產品身份，不是帳戶身份。解鎖與第一次建密碼是整頁只有 Airwave 的時候，64px 圖放在標題上。關於頁用來對版本，40px 放在版本列上就夠。Home 頂欄那格是帳戶縮寫，簽署主畫面要看的是站點與帳戶；Chrome 工具列已經有同一張擴充圖。鎖定狀態用說明文字，頂欄的鎖按鈕仍是動作，不換成產品圖。

## 為何鎖定頁也跟 locale

`airwave.settings.v1` 不是金庫。鎖定時仍讀得到語言，解鎖鈕才不會在英文使用者面前突然變繁中。
