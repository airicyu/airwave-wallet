# WHY — 0.12.0

## 點列先進詳情

整列當送出會擋住「只想看 mint／分數」。詳情是讀取；送出是明確文字鈕。

## 聚合先不送

加總不是可動用。本版詳情仍可看加總列；送出留給 combined backlog，避免可動用＝加總。

## 同一套審批

錢包送出也是未簽 VersionedTransaction。另做一頁會分叉模擬與交易費。`walletSend` 只改批准之後（送出＋等 confirmed）。dApp 路徑仍不廣播：對方可能永不送出，錢包不該空等。

## 組交易不帶 Compute Budget

與 0.11.0 未簽進殼相同：第一次省略 cu 的 simulate 跑 phase 1／1.5／2。避免 SW 組交易與 popout 各寫一套 CU。

## 「全部」用公式預留

填寫頁不打 RPC。簽名費寫死 5,000；優先費用 Default CU price × 200,000 CU。審批頁模擬才是真差額。寧願「全部」少送一點，不要把手續費打成負。

## 已送出只重等、不重送

`send` 成功但 `confirmed` 逾時時，再按批准若再廣播同一簽，可能重複上鏈。記住 `broadcastSig` 後只重查確認。關窗無法撤回。

## ATA 同筆代建

收款人沒帳戶時，分開兩筆會讓「確認一次」失敗。租金由送出者出，預期變動會看到額外 SOL。
