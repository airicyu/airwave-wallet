# 從持倉列表送出代幣 — backlog

構想尚未排進某版 INDEX，**不是契約**。排程後以該版 INDEX 為準。

收款地址簿是另一則：[address-book.md](./address-book.md)。沒有地址簿時，本項仍可手動輸入收款地址。

## 現況

Home 代幣列表只顯示目前錢包帳戶在目前 cluster 的持倉（native SOL 第一列、有餘額的 wSOL 第二列、其餘代幣）。0.7.0 起明文不做 Send。列上沒有送出入口。錢包也還沒有「自己組一筆轉帳、簽名並送出」的路徑；dApp 的 `signTransaction` 是簽完交回對方。

## 產品意向

從持倉列表的**某一列**開始，把該列的資產送到使用者指定的地址。

流程：

- 點某一列進入送出：資產已選定（名稱、符號、這一戶在該列可動用的數量），不能在這頁改送別的 mint。
- 收款地址：貼上或輸入一條 Solana 地址。地址簿若已存在，可改從白名單挑一筆填入（見地址簿構想）。
- 數量：不可超過可動用餘額；超過或不是有效數量就不能送。
- 確認頁列出資產、數量、收款地址、預估手續費（查不到寫未知，不顯示 0）。確認前必須已解鎖。
- 確認後錢包**自己組**轉帳、用這一戶能簽的密鑰簽名，並用目前 `rpcUrl` 送出。成功或失敗都給短結果；成功後持倉再查一次。

可動用餘額是**簽名那條地址**名下的數量，不是畫面上的加總。聚合錢包帳戶只從**目前能簽的那條地址**送，不從其他成員扣。唯讀或簽不了的地址不提供送出。

native SOL 走 System Transfer，並留下足夠付手續費的 SOL。其他列（含 wSOL）走該 mint 的 token 轉帳（legacy Token 或 Token-2022，跟該列的帳戶一致）。不把 wSOL 先 unwrap 再當 SOL 送。

組交易與送出在 service worker。popup 只收集地址、數量與確認。這是錢包自己的動作，不是對 dApp 開放 `signAndSendTransaction`。

## 開工前仍須拍板（排進 INDEX 時）

- 入口是整列可點，或列上一個 Send。
- 收款人尚無該 mint 的 token account 時，是否在同一筆交易裡代建，以及 rent 由誰出。
- 數量輸入用 UI 數量；全部送出時怎麼避免 SOL 手續費把餘額打成負的。
- 確認要等 `confirmed` 還是送出即結束。
- 自訂 priority fee 不在本項；若要套到這筆轉帳，排程時另寫，或接 [0.11.0](../0.11.0/INDEX.md) 的簽署 CU 規則。

## 非目標（構想層）
