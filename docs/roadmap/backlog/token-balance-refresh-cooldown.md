# 持倉刷新按鈕硬冷卻 — backlog

已排進 [0.22.0](../0.22.0/INDEX.md)，**不是契約**。以該版 INDEX 為準。

## 產品意向

錢包主畫面 Tokens 標題旁的刷新鈕（`#btn-refresh-assets`，Refresh balances）加上 **3 秒硬冷卻**。每次按下並開始刷新之後，這顆鈕暫時 `disabled`、不能再按，冷卻結束才恢復可按。

目的是同一錢包、同一畫面裡，避免使用者連按刷新、對 RPC 打太多請求。冷卻只擋這顆手動鈕；自動刷新、切帳戶、解鎖後載入等其它路徑不套這 3 秒。

冷卻是畫面狀態，不必跨畫面或跨帳戶保住：使用者離開主畫面、或切到另一個 wallet account，就可以清掉這段 disabled。回來或切回原帳戶時，鈕可以立刻再按。關閉 popup 也不必記住冷卻。

## 開工前仍須拍板（排進 INDEX 時）

- 冷卻從「按下」起算，還是等該次刷新結束才起算。構想預設從按下起算 3 秒，刷新中途與結束後都維持 disabled，直到滿 3 秒。
- 冷卻中圖示是否要額外視覺（例如維持原圖示、只靠 disabled），或 `aria-label` 要不要改成還在冷卻。

## 非目標（構想層）

- 把冷卻寫進 `chrome.storage` 或跨 popup／popout 同步
- 限制背景或定時的持倉拉取
- 在 background 做 RPC 節流或佇列
- 其它按鈕（鎖定、複製、送出）的連按保護
