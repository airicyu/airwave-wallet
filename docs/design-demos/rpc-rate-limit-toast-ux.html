RPC 速率限制 — 提示方式（概念稿）

持倉刷新若被 RPC／Helius 代理限流（HTTP 429、Kit #8100002 等）， 禁止在代幣列表下方顯示整段技術錯誤。 改為底部浮層短句，約 4 秒自動消失；可點一下立刻關閉。 若仍有快取持倉，列表照常顯示，不清空。

實作對照（給工程）

  • 文案（繁中）：「RPC 速率限制，請稍後再試」；Jupiter／Helius HTTP 429 可沿用各自已有短句，同樣走 toast。
  • 容器：沿用 popup #error + .toast-error 定位（底欄 Token／Activity 上方）。不加新 popout。
  • 語意：限流／可重試的 RPC 失敗 → toast only；#home-assets-error 不顯示 Kit decode 字串。
  • 部分成功：rows 有資料 + 背景刷新失敗 → 保留列表 + toast（右下概念）。
  • 全失敗且無快取：仍 toast；列表區可為空或「載入中」結束後無列，不要長段紅字。
  • 偵測：訊息含 8100002、429、rate limit、「速率限制」等 → 視為同一類（見 friendly-error-message.ts）。
